# CPA Quota

为 [CLIProxyAPI（CPA）](https://github.com/router-for-me/CLIProxyAPI) 提供 **Codex 额度周期自动激活、账号调度和对外数据 API**。既能在后台维护额度窗口，也能让其他客户端、面板或服务读取账号池状态与用量。

源码仓库：[lexy76888-dev/cpa-plugin](https://github.com/lexy76888-dev/cpa-plugin)。插件 ID 为 `cpa-quota`，显示名称为 `CPA Quota`，当前构建目标为 Linux/amd64。

## 主要功能

| 功能            | 用途                                                                                 |
| --------------- | ------------------------------------------------------------------------------------ |
| 自动小请求      | 新额度周期到期但尚未激活时，先检查额度，再按条件发送一次小模型请求，并复查实际结果。 |
| 周额度周期维护  | 按账号已知周重置时间唤醒，及时激活下一周期，减少等待首次业务请求造成的周期延后。     |
| 5h 定时探测     | 按配置的时区和每日时刻检查 5 小时窗口，支持手动触发、启用和停止自动激活。            |
| 账号调度        | 按真实可用性、优先级、到期时间及剩余额度选择账号，处理额度耗尽与故障熔断。           |
| 对外额度 API    | 一次读取账号额度、冷却、近期请求、价格和周期费用估值，可供其他程序接入。             |
| 管理 API 与页面 | 查询队列及探测状态、修改设置、刷新额度、查看日志、维护分组备注和导入导出配置。       |

## 自动小请求、周窗口和 5h

这里的小请求用于激活新额度周期，不是持续发送业务请求。当前源码使用 `gpt-6-luna`，输入为 `hi`；模型并不是页面中的可配置项。每次先读取额度，仅在确认需要激活时才发送，请求后再检查新窗口是否成立。失败或结果未知不会当作激活成功。

- **周窗口**：在已知周重置时间后唤醒并复查，需要激活时可直接发送，不必等待 5h 的每日排程。这个机制帮助稳定周期衔接，但最终重置时间由上游返回，插件不能强制指定星期几或改变额度总量。
- **5h 窗口**：可以配置每日触发时刻，例如 `07:00 / 12:00 / 17:00`；窗口仍活跃时只检查，不重复激活。还可设置允许发送小请求的时间段。
- **启用／停止**：在页面“调度设置”中勾选或取消“自动新周期探针”，再保存。它对应 `enable_reset_probe`，默认关闭，目前同时控制周窗口和 5h 激活，并不是两个独立开关。停止后不再授权新的自动激活；已发出的上游请求无法撤回。
- **立即探测 5h**：不必等下一排程，但仍需先启用探针，并遵守允许发送的时间段、账号有效性及并发保护。

探针在后台运行，不依赖页面保持打开；运行状态会持久化，重启后先核对未决结果，避免重复发送。小请求可能消耗少量额度。具体排程、默认值和控制方式见[调度与周期激活说明](docs/scheduler.md#自动小请求与额度周期)。

## 提供给其他程序的 API

两类接口使用不同凭据：

| 接口                                                      | 内容／动作                                     | 认证         |
| --------------------------------------------------------- | ---------------------------------------------- | ------------ |
| `GET /v0/resource/plugins/cpa-quota/snapshot`             | 账号、额度、冷却、近期请求、价格和周期费用快照 | 独立只读令牌 |
| `GET /v0/management/plugins/cpa-quota/status?format=json` | 调度队列、可用状态、5h／周窗口及探测结果       | CPA 管理 Key |
| `GET /v0/management/plugins/cpa-quota/settings`           | 读取完整运行设置                               | CPA 管理 Key |
| `PUT /v0/management/plugins/cpa-quota/settings`           | 保存设置，包括探针启停与排程                   | CPA 管理 Key |
| `POST /v0/management/plugins/cpa-quota/probe/trigger`     | 手动触发一次 5h 探测                           | CPA 管理 Key |

只需展示数据的客户端使用快照接口；需要控制调度与探针的程序使用管理 API。快照依赖 CPAMP，管理 API 直接使用 CPA 插件运行状态。只使用调度和周期激活时，无需配置 CPAMP 快照。

接入说明：[额度快照配置与读取](docs/status-snapshot.md) · [完整管理 API 与启停示例](docs/scheduler.md#management-api)。

## 构建与安装

需要 Go 1.26+、make 和支持 CGO 的 C 编译器。在 Linux/amd64 上执行：

```sh
make check
```

将生成的 `dist/linux-amd64/cpa-quota.so` 放入 CPA 配置的插件目录下 `linux/amd64/` 子目录，再启用插件：

```yaml
plugins:
  enabled: true
  configs:
    cpa-quota:
      enabled: true
      priority: 1
```

重启 CPA 后，在插件列表确认 `CPA Quota` 已注册并启用。Docker 部署需挂载插件和配置目录。只编译用 `make build`；打包用 `make package`，默认版本为 `dev`，发布时通过 `VERSION` 指定版本。非 Linux 主机需配置 Linux/amd64 的交叉 C 编译器，产物须与服务器 libc 兼容。

## 页面使用

在 CPA 管理中心打开“Codex 调度器”，或访问 `/v0/resource/plugins/cpa-quota/status`，填写 CPA 管理 Key 后加载数据。

- **5 小时额度探测**区域显示启用状态、排程、末次确认、账号结果和错误；“立即探测 5h”执行一次手动检查。
- **调度设置**控制账号接管、用量反馈、自动探针、刷新及熔断策略。关闭账号接管与关闭自动探针是两个不同操作。
- **账号队列**显示额度、重置时间、可用状态和优先级，支持单账号刷新、别名、分组、标签和备注。
- **日志与导入导出**用于查看探测结果、排查失败和保存设置。

## 说明与致谢

插件在 CPA 进程内运行，状态目录为服务用户的 `~/.config/CLIProxyAPI/cpa-quota/`。设置与备注存于 `.user-data.json`（格式版本 1），调度和凭据事务状态存于 `.runtime-state.json`；不支持的设置格式会保留原文件并拒绝加载。管理操作使用 CPA 管理认证，额度快照使用独立只读令牌，不能混用。真实密钥、账号文件和运行数据不要提交到 Git。
